# TMK WorkFlow

Сайт коммерческой недвижимости TMK WorkFlow (Алматы): аренда офисных и
коммерческих помещений в бизнес-центрах **Time Square**, **Venus** и
**Koktem Towers**.

Домен: https://tmk-workflow.kz/

## Структура

| Страница          | Маршрут           | Что на ней                                        |
|-------------------|-------------------|---------------------------------------------------|
| Главная           | `/`               | Хиро-блок, форматы офисных решений, сервисный офис, полный блок Time Square, переходы на Venus и Koktem Towers |
| Venus             | `/venus`          | Полный блок объекта                                |
| Koktem Towers     | `/koktem-towers`  | Полный блок объекта                                |
| Политика          | `/privacy`        | Обработка персональных данных                      |
| CRM               | `/crm`            | Обработка заявок: фильтры, таблица лидов, карточка лида |

Блок объекта одинаков для всех трёх страниц и идёт в порядке ТЗ: большое фото →
информация → экосистема TMK → свободные площади и характеристики → преимущества →
фотогалерея → запись на просмотр.

## Технологии

- React 19 + TypeScript
- Vite 7
- Tailwind CSS 3 (палитра: голубой, белый, оранжевый)
- React Router 7
- Lucide React — иконки
- Vercel Serverless Functions — приём заявок и CRM
- PostgreSQL — база лидов CRM (postgres.js)

## Запуск

```bash
npm install
npm run dev
```

Функции из `api/` работают и в `npm run dev`: dev-сервер Vite поднимает их сам,
читая секреты из `.env`. Отдельный `vercel dev` не нужен.

> При локальной проверке форм помните, что `RESEND_API_KEY` из `.env` отправляет
> настоящие письма. Уберите ключ, если письма слать не нужно.

Сборка и проверки:

```bash
npm run build
```

```bash
npm run lint
```

## Где что лежит

```
src/
  lib/properties.ts      — весь контент объектов: тексты, площади, характеристики,
                           преимущества, фотографии и alt-тексты
  lib/homeContent.ts     — контент главной (хиро, форматы, сервисный офис)
  lib/site.ts            — контакты, WhatsApp, обёртка над аналитикой
  lib/leadForm.ts        — маска телефона, валидация, отправка заявки
  components/property/   — секции блока объекта
  components/home/       — секции главной страницы
  components/lead/       — форма заявки и модальное окно
  crm/                   — интерфейс CRM: вход, таблица лидов, карточка лида
shared/crm.js            — справочники и схема полей CRM: общий модуль для
                           браузера и серверных функций
api/lead.js              — приём заявки: письмо, реестр и лид в CRM
api/crm/                 — серверные функции CRM
api/_lib/                — общий код функций: база, сессия, лиды, CSV
```

Чтобы поправить текст, площадь или список фотографий объекта — правится только
`src/lib/properties.ts`.

## Заявки с форм

Формы отправляют `POST /api/lead`. Функция валидирует данные, отсекает ботов
(honeypot + минимальное время заполнения + ограничение частоты по IP) и
рассылает заявку по трём каналам сразу: письмо через [Resend](https://resend.com),
запись в Google-реестр и лид в CRM.

Переменные окружения на Vercel:

| Переменная        | Обязательна | Значение по умолчанию                        |
|-------------------|-------------|----------------------------------------------|
| `RESEND_API_KEY`  | да          | —                                            |
| `LEAD_TO_EMAIL`   | нет         | `yerlepessov.t@tmk-limited.com`              |
| `LEAD_FROM_EMAIL` | нет         | `TMK WorkFlow <noreply@tmk-workflow.kz>`     |
| `LEADS_REGISTRY_URL`   | нет    | приёмник Google-реестра                      |
| `LEADS_REGISTRY_TOKEN` | нет    | общий секрет реестра                         |

Домен отправителя должен быть подтверждён в Resend, иначе письма не уйдут.

В письме передаются: объект, страница, источник формы, имя, компания, телефон,
email и комментарий.

## CRM

CRM живёт по адресу `/crm` и обрабатывает заявки с сайта: фильтры, таблица
лидов, карточка лида, ручное добавление и выгрузка в CSV.

### Доступ

Вход по одному общему паролю, без логина. Пароль задаётся переменной
`CRM_PASSWORD`. В cookie кладётся не пароль, а срок действия сессии и подпись
HMAC, поэтому смена пароля обесценивает все выданные сессии.

Страница закрыта от индексации: `Disallow: /crm` в `robots.txt` и `noindex` в
разметке самой страницы.

### Переменные окружения

| Переменная           | Обязательна | Назначение                                      |
|----------------------|-------------|-------------------------------------------------|
| `CRM_PASSWORD`       | да          | общий пароль входа                              |
| `DATABASE_URL`       | да          | строка подключения к PostgreSQL                 |
| `CRM_SESSION_SECRET` | нет         | ключ подписи сессии; по умолчанию из пароля     |

`DATABASE_URL` подходит от любого провайдера: Neon, Vercel Postgres, Supabase,
Railway. Берите строку с пулером — функции Vercel открывают много коротких
соединений. Отдельная миграция не нужна: таблица `crm_leads` и индексы
создаются сами при первом обращении, все выражения идемпотентны.

Из адреса подключения убираются параметры libpq (`channel_binding`,
`sslrootcert`), которые Neon и Supabase добавляют в свои строки. Без этого
драйвер отправляет их серверу как настройки соединения, и Postgres обрывает
подключение с «unrecognized configuration parameter» — см. `withoutForeignParams`
в [api/_lib/db.js](api/_lib/db.js).

### Справочники

Статусы, причины отказа, форматы офиса и остальные списки лежат в одном модуле
[shared/crm.js](shared/crm.js). Его читают и браузер, и серверные функции:
выпадающие списки в интерфейсе, проверка значений на сервере и заголовки
колонок CSV берутся оттуда и не могут разойтись.

Список ответственных менеджеров — массив `MANAGERS` в том же файле. В ТЗ он
помечен как «предоставляется отдельно», сейчас там заглушка: замена списка —
правка одного массива.

### Условная логика полей

Раздел 10 ТЗ описывает зависимости полей от статуса. Правила заданы один раз
функцией `requiredFieldsFor` и применяются дважды: карточка подсвечивает
незаполненные поля, сервер отклоняет сохранение. Проверка на сервере считается
по итоговому состоянию лида, поэтому частичное сохранение правило не обходит.

| Статус             | Что происходит                                              |
|--------------------|-------------------------------------------------------------|
| Просмотр назначен  | появляется блок просмотра; объект, дата и время обязательны  |
| Просмотр проведён  | обязателен комментарий по результату просмотра               |
| Отказ              | обязательна причина отказа                                   |
| Сделка             | появляется блок итоговых параметров сделки                   |

Свободное поле «Желаемая локация» появляется, когда интересующий объект —
«Ищет другой объект / офис».

### Заявка с сайта в CRM

Заявка уходит по трём независимым каналам одновременно: письмо менеджеру,
Google-реестр и лид в CRM. Ни один канал не отменяет другие — недоступная база
или реестр не мешают письму, а отсутствие ключа почты не мешает записи лида.

Поля формы переносятся в карточку как есть. «Формат офиса» в форме нет, поэтому
он выводится из кнопки, которой форму открыли: «Подобрать сервисный офис» →
«Сервисный офис», «Подобрать офис» → «Офис», остальные точки входа →
«Не определился». Менеджер может изменить значение в карточке.

`gclid` и UTM-метки берутся из cookie, куда их кладёт `captureAdParams` при
первом заходе, и сохраняются в карточке лида. В таблицу они не выводятся.

### Выгрузка CSV

`Экспорт CSV` выгружает лиды с учётом активных фильтров, без ограничения
страницей. Разделитель — точка с запятой, в начале файла BOM: Excel с русской
локалью открывает такой файл сразу колонками и не ломает кириллицу.

### UX/UI

ТЗ (раздел 17) просит не переносить исходный шаблон один в один, а сделать
1-2 итерации улучшения. Что сделано:

**Первая итерация — структура.** Закреплённая шапка и панель действий; поиск,
фильтры, обновление, выгрузка и добавление лида в одном ряду; панель фильтров
сворачивается, а выбранные условия остаются видны чипами и снимаются по одному;
таблица с сортировкой по колонкам, цветными метками статусов и оранжевой
полосой у необработанных заявок; карточка лида разбита на разделы ТЗ с
навигацией по ним.

**Вторая итерация — поведение.** Каркас строк вместо прыжка вёрстки при
загрузке; тонкая полоса обновления поверх уже показанных данных; понятное
пустое состояние с кнопкой сброса фильтров; уведомления о результате действия;
поиск с задержкой, чтобы не дёргать сервер на каждую букву; подтверждение при
закрытии карточки с несохранёнными правками; прокрутка к первому незаполненному
обязательному полю; клавиша «/» ставит курсор в поиск, Esc закрывает карточку.

Интерфейс работает и на телефоне: таблица прокручивается внутри своей карточки,
карточка лида раскрывается снизу на всю ширину.

## Аналитика

`track()` из `src/lib/site.ts` отправляет события в `dataLayer`, `gtag`, `ym`
и `fbq`, если счётчик подключён на странице. События: `lead_form_open`,
`lead_submit`, `phone_click`, `whatsapp_click`. Идентификатор Яндекс.Метрики
задаётся переменной `VITE_YM_COUNTER_ID`.

## Деплой

Vercel, framework preset **Vite**. Настройки в `vercel.json`: сборка в `dist`,
SPA-rewrite всех маршрутов кроме `/api/*`.
